# Capability matrix

Research snapshot: 2026-10-03; immutable source links below, revisions in SOURCES.json.

- VERIFIED: the scoped claim is evidenced by an official example, implementation
  or documented contract. For upstream columns this means their own platform,
  not portability or our hardware validation. GPIO's CM0 evidence is upstream's
  reported read test, not a WiliPirate bench result.
- POSSIBLE: an API or plausible integration exists, but CM0 end-to-end semantics,
  result delivery, electrical setup or device version still require validation.
- UNSUPPORTED: explicitly unavailable on the specified transport, or deliberately
  excluded from V0.1 as stated. It does not imply impossible hardware.
- UNKNOWN: the inspected sources did not establish the capability; no fabricated API.

FREE-WILi API classifications concern usable CM0 application access. API method
existence alone is not proof of every result/event path. V0.1 is the small
planned product scope; **the delivered M1 scaffold implements none of these
hardware operations**. Only HiZ/help/info/mode/exit are available. There are no
simulated ACKs or working protocol modes.

UART, I2C and SPI share firmware-controlled configuration and power prerequisites.
None inherits Bus Pirate pin protection, pull-ups, supply limits or selectable
voltage guarantees. Bit Pirate radio and extended buses may require add-on
hardware. Display/internal pin mappings must not be treated as user-header maps.
See ARCHITECTURE.md for target-power/GUI APIs, limitations and the proposed first
GPIO read-only test. No probing, protocol writes or RF operations were performed.
